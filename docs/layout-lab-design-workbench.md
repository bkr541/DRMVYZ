# Layout Lab blank canvas

Layout Lab opens a blank canvas shaped like the React View: a **blank header group** across the top, a **blank navigation column** on the far left, an **empty left window**, an **empty middle visualizer**, an **empty right window**, and the **bottom audio dock**.

There are no dropdowns or other selectors anywhere: no design picker, no engine picker and no inspector tabs; the header group and navigation column are empty surfaces. The windows and visualizer contain no content, and the rails have no collapse handles.

**Dimensions match React.** The canvas is built from the same markup and classes as the app (`FloatingWorkspaceFrame` → `.fw-app-shell` → `.vz-main` → `.rv-shell--floating` → `.rv-layout`, rails with `rw-frame--left/right`, the dock as the shell's second grid row), so every size comes from production's own CSS: the 9px outer inset, 11px gaps, 22vw clamped rail width and 106px dock. A blank header group sits across the top (the production header surface, 60px, with nothing in it) and a blank navigation column on the far left (the production compact navigation surface, 72px wide, empty), so the stage region is the same size and position as in the app. Measured against the real `ApplicationWorkspaceFrame` (real header and sidebar) at 1600×1000, 1280×800 and 1000×700, the left window, visualizer, right window and dock rectangles are identical (1600×1000: windows 352×794, visualizer 773×794). The visualizer is the stage above the dock. In design A it shares its column with the Track Map workspace, as in React, so its height matches the app's (773×529 at 1600×1000); designs B–E have no workspace under theirs, so their visualizers are taller.

**Ten designs, A–I and K.** Ten buttons labelled A, B, C, D, E, F, G, H, I and K are pinned to the bottom of the navigation column as a compact 2 × 5 grid of 26px keys (J is intentionally skipped). A–F are dedicated compositions; H, I and K each use the original base React View styling, and G uses it with four surface-level changes (neutral charcoal palette, matte grain, monoline icons, Manrope; `layoutLabOptionGStyle.css`, scoped to `design-07`) and content, independent of one another. Each button selects one of ten independent designs (the old Layout Lab's design options): only the selected design is shown, a design is mounted the first time it is selected and then stays mounted and hidden so each keeps its own state (an unvisited design costs nothing), and the selected button is highlighted. Every design is a full copy of the page (header group, navigation column, windows, visualizer, dock) with its own switcher, so any view can change the selection. All five start with identical geometry; each is themed through `.ll-design-workbench[data-lab-design='design-0N']` rules in `layoutLabDesignWorkbench.css` (A is `design-01`, E is `design-05`, F–I and K are `design-06` to `design-10`), and the catalog lives in `layoutLabDesignCatalog.ts`.

**Design A mocks the React header, the navigation bar and the Cinema 2.0 windows.** Its navigation column holds the production left-nav options (`LayoutLabReactNav.tsx`): React (active), the Managers label, Preset, Show, Lyric and Media Manager, and the licence and version footer, in the compact sidebar's markup and classes. Clicking an option only moves the highlight; nothing routes, and there is no audio-engine check on Show Manager. The A–E switcher sits between the options and the footer. Its header group holds the elements React View puts in the application header (`LayoutLabReactHeader.tsx`): the DRMVYZ brand toggle, the centred output controls (OUTPUT PREVIEW, Reveal, Blackout, shown idle as in production's non-LaserDMX state), the Layout Lab button, the status cluster (Loading / Saved, FPS / Frame Time, Quality / CPU, Notifications) and the profile button. It reuses the presentational production pieces (the brand toggle, header control group, metric chip, metrics builder and bell icon) and production's classes, with fixed readings rather than the stores, output controller, CPU probe and account lookup; nothing in it acts on anything. Its left window is React View's left rail with Cinema 2.0 / Electric Storm active (`LayoutLabElectricStormLeftWindow.tsx`): the React Workspace header, the engine card, SOURCE / LAYERS tabs, and the Media Library group with its filter tabs, search, grid/list toggle and a 24-tile media grid; the LAYERS tab is production's own Cinema 2.0 layers list (`Cinema2LayersList`, split out of `Cinema2LayersPanel`, whose behaviour is unchanged), given the layers the production compiler produces from Electric Storm's manifest: its one layer, "Electric Storm", 100% · normal. A third tab, **NOTICE**, to the right of LAYERS (`LayoutLabNoticeTab.tsx`), shows production's own `NoticeCard` in each of its four looks, Info, Success, Warning and Error (the destructive look), one parent group per tone with the card's variants stacked: title and body, title only, with the hover dismiss control, and with dismiss and open. Dismiss hides a card (switching tabs restores them) and open does nothing; there is no store or notifications drawer. Its right window is the Inspector's DESIGN tab with the MARQUEE preset loaded (`LayoutLabMarqueeRightWindow.tsx`): PRESETS / DESIGN / REACT / AUDIO / TRACKS, ENGINE / SELECTION, and the four parent groups (Master Controls; Design with Pattern, Marquee Copy and Lighting Zones; Effects; Palette) with the preset's real labels, ranges and defaults, starting on the values in the production screenshot. Both are built from the production components and classes (`RailWindowHeader`, `RailTabs`, `Collapsible`, `UnderlineTabs`, `PanelSubtabs`, the control rows, the media sheet card classes) with local state only, so they match production's look and respond to input but touch no store, runtime or media service. They are the only dropdowns on the canvas (Pattern and Trigger, and the engine card, which opens nothing). Its inspector's other tabs are mocked too. **PRESETS** is the Cinema 2.0 preset browser (`LayoutLabCinema2PresetsTab.tsx`): SYSTEM / USER, the search row and the two-column poster grid of the presets Cinema 2.0 really ships, read from the engine registry with the same filter as production; the production panel's account-catalog lookup is left out because it calls the backend, and loading a preset only moves the highlight. **REACT** is the Canvas engine's routing surface (`LayoutLabCanvasReactTab.tsx`): ROUTING / ANALYSIS with Effects first, then Performance Automation, Motion and Preset FX (production's order), shown for the Glitch Pulse preset (a standard preset that declares both FX and Motion) with production's labels, ranges, colours, defaults and option lists; Auto Performance and Pool Automation switch each other off and gate their dependants as the production handlers do. ANALYSIS is empty because it renders live diagnostics. The fourth tab, **AUDIO** (in place of OUTPUT), is the Audio Intelligence window from the Track Timeline Visualizer (`LayoutLabAudioIntelligenceTab.tsx`): the real `MusicIntelligenceDiagnosticsPanel` with its Track header grid, window header and every section (Audio Bands, Rhythm, Beat Grid, Musical Phrases, Energy, Measurements, Section, Section & Structure, Event Markers, Harmonic, Stems, Lyrics, Semantic). It reads a fixed frame and analysis from `layoutLabAudioIntelligenceFixture.ts` instead of the live audio bus, through the panel's optional `frameSource` prop (which defaults to the bus, so production is unchanged). Values differ field to field on purpose: bars run from near-empty to full, some dots are lit and some not, and every section has text, so each state can be reviewed with no audio playing. A fifth tab, **TRACKS**, to the right of AUDIO, is the Lyric Manager's Tracks tab (`LayoutLabLyricTracksTab.tsx`): production's own `LyricTrackBrowser`, unchanged, inside the `.lmv-workspace-tab-panel` the Lyric Manager hosts it in: the search field and filter dropdown, the track list of `AudioTrackCard` rows (Selected dot, Loaded and Playing badges, Load, AI Extract and overflow actions), the selected track's lyric versions nested in its card (Active and Open badges, rename / duplicate / make active / delete, New version and Import version), the unattached legacy documents under the list, and Load More. Production scopes that panel's spacing and row bleed under `.lmv-left-rail`, so the tab's wrapper carries that class and the workbench CSS clears the rail's own surface. The placeholder library (`layoutLabLyricTracksFixture.ts`) has ten tracks plus a Load More page: tracks with and without an artist, BPM, key and active lyrics, tracks needing review, a first track with five versions (every import source, one with no cues, one with an artist) and a second that can be loaded and played. Every record starts collapsed and plain; clicking one selects it (wash, cyan left bar, its versions nested in the card) and clicking it again collapses it, and Load (then Load again) shows the Loaded and Playing badges. Selection, loading, search, filtering, open / make active, rename, duplicate, New / Import version and Load More work on local state; deleting a track or a version and the AI Extract hand-off do nothing, and the loading and error states, which production shows only during a fetch, are not reachable.

**Designs C–E are full copies of React View's mockup; B has its own player and icon family; A is its own composition (below).** `buildDesignWindows` in `LayoutLabDesignWorkbench.tsx` gives each of those options the same mockup content: the React header, navigation column, Electric Storm left window, MARQUEE inspector, Lyric Manager Track Timeline and Cue list, Track Map, Settings and Pop-ups & Dialogs groups, and the audio dock, each with its own state (editing Option B changes nothing in Option A). Each header names its design at the top left, beside the brand toggle: "Option A", "Option B", … "Option E" (`.ll-option-label`, which hangs off the toggle so the centred output controls stay where production puts them). The Settings pop-up takes a per-design id prefix; the production views inside it still use fixed element ids, so a hidden design's label-to-field links in the Settings tabs can resolve to another design's field. The media tiles are gradient placeholders, not the library's artwork.

**Design A's Lyric Manager Track Timeline and Cue list sit above the Track Map.** `LayoutLabLyricManagerWindows.tsx` mounts production's own `LyricTrackTimelineWindow` with `LyricCueStackedTimeline` (the "Track Timeline" group: Time, Beats, Sections and Audio rows over the Lyrics 1–3 lanes, with the row labels shown and one playhead across every row) and, right below it, `LyricCuesWindow` (the "Cue list" group: cue count, search, the filter dropdown, the # / Time / Lyric / Status table and the expanded cue editor with its word timings), all unchanged, so the classes, row heights and colours are the Lyric Manager's. As in the app the two are siblings over one cue editor: one set of cues, one selection, one playhead (with undo and redo), and the list's filter fades the cues it hides in the lanes. Only the data is local (`layoutLabLyricTimelineFixture.ts`): the same 119 s track as the Track Map (its beat grid, its twelve sections, the dock waveform's peaks) and 24 placeholder lyric cues covering every state: playing, selected, low confidence, empty, an unmarked overlap and a word that runs past its cue (warnings and warning counts), all four review statuses, cues with word timings (one with a low-confidence word and one invalid) and one without, ad-lib overlaps that open a third lane, and one block past the visible lanes. A cue is faded only by choosing a filter, as in production. Each group collapses and expands from its header (the Track Map does it from its toolbar); the wrapper carries only the lyrics workspace's floating-window attributes so the windows' surface rules apply, and has no box of its own. Click or drag the reference rows to scrub, scroll over the lanes to zoom, and select, drag, add or right-click cues as in the app; nothing is saved. `LyricCueStackedTimeline` and `LyricCuesWindow` take the narrow `LyricCueStackedTimelineEditor` and `LyricCuesWindowEditor` slices of the cue editor so the mockup can feed them local state. Production leaves the Track Timeline's `actions` and `toolbar` slots empty (cue editing is in the Lyric Manager header and playback in its preview panel), so they are not part of the mockup.

**Design A's Settings pop-up is drawn inline below the Track Map.** `LayoutLabSettingsWindow.tsx` is a collapsible "Settings" group (the same window treatment as the Lyric Manager's) holding the production pop-up's own surface, `SettingsModalFrame` (split out of `SettingsModal`, whose behaviour is unchanged): the SETTINGS header and close button, the section navigation (Account, Appearance, Brand Kit, System Settings, DJ Software, Developer, Sign Out) and the content pane, at production's height and with its border, radius, shadow and colours; only the width follows the column. Each tab is the real panel markup, split out of its stateful panel into a view that the panel still renders: `AccountPanelView`, `AppearanceSettingsView`, `SystemSettingsView`, `DjSoftwareSettingsView`, and the Developer panel, whose Logging table takes an optional `preview` of log entries instead of reading the desktop app's main.log. They are fed placeholder state (`layoutLabSettingsFixture.ts`): a signed-in profile, a synced Rekordbox index of 2,418 tracks, and a 14-line log covering every level and component, with an expandable multi-line error. Close collapses the group; Sign Out does nothing; theme, quality, DJ software, search and filters change local state only, so nothing is applied to the app, saved or signed out. **The Brand Kit tab is not mocked yet**: it is the most store-bound panel (six components read the Brand Kit, media and React stores), so its tab shows a placeholder line.

**Design A's pop-ups and confirmation dialogs are drawn inline in a "Pop-ups & Dialogs" group below the Settings group.** `LayoutLabPopupsWindow.tsx` shows each one in a captioned stage that stands in for the app window (the caption names where the app shows it), in four tabs. **CONFIRMATIONS** (18) are the shared `ConfirmDialog` with the exact titles, messages, notices and buttons each caller gives it: Delete Media Item / Items (and while working), Delete Track, Delete Collection, Delete Pool, Delete Show (and while deleting), Change Section Engine?, Delete Deck, Delete Beam / Beams / Group, Camera Access Needed, Unsaved changes (and save failed) and Save As (and failed). **LYRIC MANAGER** (7): Delete Track, Delete Lyric Version, Replace active lyric version?, Unsaved lyric changes, the cannot-be-dismissed version conflict, and the recovered-draft dialog (Review open, and the server-conflict variant). **EDITORS** (6): Edit Audio Metadata (and its validation message), New and Edit Collection, and the Audio preview (error and loading). **MENUS & PANELS** (6): the track actions menu, the library context menu with its Add to Collection flyout, the cue point menu (existing cue, empty spot), the Notifications drawer (all four tones; it closes and reopens) and an Info popover (click the trigger). The dimmed backdrops and cards are production's own classes; the fixed backdrops are laid in flow (`.ll-popup-stage` in the workbench CSS) so each stage takes its dialog's height, and the menus lose their fixed positioning. The wrappers that own their copy are mounted as they are, and the store-bound modals and menus were split into views their production components still render (`UnsavedMediaChangesView`, `AudioTrackEditView`, `CollectionEditorView`, `AudioTrackPreviewView`, `ContextActionMenuSurface`, `CuePointContextMenuPanel`). Buttons close and save nothing. Not mocked: the Media Upload and Media Preview modals (large stateful media flows), the New Show form dialog, the Cast Output popover (native display bridge) and the separate OS windows (Layout Lab, Track Timeline Visualizer); the Audio dock's popovers are live in the dock, and a lyric cue's menu opens on right-click in the Track Timeline.

**The middle column scrolls.** The center column (the visualizer and every window under it) scrolls vertically, with the Lyric Manager's 5px scrollbar, so more production windows can be stacked below. The visualizer keeps a minimum height (`--ll-visualizer-min-height`, 360px) instead of shrinking, and takes the spare height while the groups are collapsed. At 1600×1000 the column is 773×794: visualizer 360px, Track Timeline 327px, Cue list 354px and the Track Map 254px, 1328px of content in all.

**Design A's Track Map workspace mirrors React's.** `LayoutLabReactTrackMap.tsx` is the performance timeline workspace under the visualizer: the toolbar (Track Map / Performance Pads, the row-icons key, Cast, Stage Focus, the collapse chevron), production's resize handle, and the Track Map surface with its lanes in production's order: Beats, Sections, the marker rows (Cues, Phrases, Moments, Actions) and the Time ruler, with the shared playhead. It uses production's own pieces where they stand alone (the real `SectionTimeline`, the beat-grid and ruler canvas drawing, the lane icons, the cue row layout and staggering, the section detail overview) and its markup and classes elsewhere, fed placeholder data from `layoutLabTrackMapFixture.ts` so every row and mark kind shows: an imported Rekordbox beat grid at 129 BPM; twelve sections covering every section type, from Rekordbox, automatic, user-edited, user-created and fallback origins, four with preset badges; Rekordbox hot cues A–H, memory cues and loops beside two manual cues (with bar, beat and snap detail in their titles); structural phrases; semantic moments; and preset and PixGrid actions, one disabled. Click a section for its detail overview (bars, intensity, preset, confidence tier, family and occurrence), a marker to move the playhead, and drag the handle to see the lower rows. Boundary dragging, the section editor and context menus are not part of the mockup. Performance Pads is an empty tab. The embedded Track Map shows no Rekordbox title / artist / BPM / key header; those appear in the Track Timeline's Audio Intelligence window, which is the AUDIO tab.

**Design A's dock mirrors React's.** `LayoutLabReactAudioDock.tsx` is written from the production dock (`VyzualzAudioDock` as React mounts it: `expandable`, `showAudioSourceControl`, Track Timeline key in the lower slot): the same three regions and cards, previous / play / next, volume, Replace Track, waveform and zoom keys, the BPM block with its scrub bar, the Source line, TAP / CUE / SYNC, the Playlist and Track Timeline keys, the Audio Source popover (Input and Rekordbox menus) and the Playlist popover, and click-empty-space-to-collapse. Its state is local (a three-track queue, a fixed 129 BPM), so nothing plays or loads. The waveform is production's own deck canvas (`RgbWaveformCanvas`, as `PeaksWaveformView` renders it in React) drawing a generated loaded-track analysis (`layoutLabWaveformFixture.ts`: a quiet intro, build, drop, breakdown, second build and drop, and outro) with five cue flags and the playhead; the zoom keys zoom it, clicking it moves the playhead, and the playhead advances while Play is on. No audio is decoded or heard. Checked against the real dock in a browser at 1600×1000 and 1280×800, every region, card, key and block lands on the same rectangle; the only difference is the width of the BPM figure, which follows its text (that comparison was made before the waveform canvas was added; the canvas sits in the same waveform slot). Designs B–E keep the older dock mockup described next.

The dock is the existing disconnected dock mockup (`TemplateAudioDockMockup`), which uses the production dock classes and has local-only state. It contains no dropdowns. Its text labels on TAP / CUE / SYNC are hidden (production's keys are icon-only and the labels overflowed the dock grid).

**Option A "Instrument Rack".** Option A is its own composition, not a skin on React View's: `LayoutLabDesignWorkbench` hands design A to `optionA/OptionAWorkspace.tsx`, which builds the whole window from Option A's own components, while designs B–E keep their existing frame, shell and rails (nothing of Option A's markup or classes appears in them). The design is drawn from two references, a plug-in with matte graphite modules, ring-lit knobs, square LED switches and a rack of list rows, and a pair of hardware modules with inset displays, thin ring gauges and extended numerals. What carries over is the construction: modules are soft slabs (26px radius), every readout lives in an inset display, level and tempo are knobs and rings, status is a square LED, titles are large and light (Manrope 200–300) while labels and numerals are tiny and extended (Michroma), and light is the only colour (ember for what is on, ice for what is secondary, red for live, white for the primary key).

- **Composition.** A full-height spine at the left (brand disc, the five destinations as hardware keys, the Layout Lab selector, untouched, and the licence readout); beside it a header strip above the working area only; then a 344px workspace module, the stage with its rack of windows, a 380px inspector module, and a 148px deck of three instruments. The stage is the first item of a scrolling column.
- **Rebuilt as Option A components** (`optionA/`): header (`OptionAHeader`: output keys, ring gauges for FPS and CPU, an LED ladder for quality), spine, window heads, the engine display, the bank-key tabs, the Media Library (segmented filters, inset search, tiles with captions under the picture, list rows), Layers, the Notice tab and its card, and the Inspector DESIGN tab (rack groups, rotary knobs, ticked faders, LED switches, selects, fields and swatches, from `oaControls.tsx`), the stage frame with working Grid and Safe-area guides, and the dock (`OptionADock`: a deck with a progress-ring Play key and a level knob, a scope drawn by `OaScope` from the same analysis the production waveform reads, and a draggable BPM ring dial with the transport keys, source readout and the Audio Source and Playlist popovers).
- **Wrapped, not rebuilt.** Production's large store-shaped surfaces are mounted inside Option A's frame and skinned by `optionAWrapped.css`: the Lyric Manager Track Timeline and Cue list, the Track Map, the Settings and Pop-ups & Dialogs mockups, and the Presets, React, Audio and Tracks tab bodies. Cue, section and lane colours, preset thumbnails, media art and the Appearance theme previews are authored data and keep their own colours.
- **Isolation.** Every selector in `optionA.css` and `optionAWrapped.css` contains an `oa-` class; portaled popovers and menus carry `oa-popover` / `oa-menu` (the tokens are declared on those classes too). Options B–E were measured with and without these stylesheets across every element and every computed property: no differences other than the mid-flight values of production's own pulse animations. The only edits to shared files are `export` keywords on fixtures that Option A reuses (`LayoutLabElectricStormLeftWindow`, `LayoutLabMarqueeRightWindow`, `LayoutLabNoticeTab`).
- **Typography.** The shared role tokens in `typography.css` are not changed; Option A sets its own `--type-*` values under `.oa-root`, so the window-title / nested-title hierarchy holds (large light titles, small tracked nested labels) with Option A's faces.
- **Not mocked / limits.** The Brand Kit Settings tab is still a placeholder, and the Media Upload and Media Preview modals, the New Show form, the Cast Output popover and the OS windows are not drawn. The Settings pop-up's production views use fixed element ids, so with several designs mounted a label can resolve to another design's field.

The canvas mounts no production rendering, audio, or media runtimes and makes no changes to saved projects. Closing Layout Lab discards its local state.

Structure lives in `LayoutLabDesignWorkbench.tsx`; popup stylesheet mirroring (`LayoutLabModal.tsx`) is unchanged. The earlier component studies and workspace previews (`LayoutLabReferenceMockup`) remain in the source as references and are no longer mounted by Layout Lab.

`__tests__/LayoutLabDesignWorkbench.test.tsx` covers the A–E switching and independent state, plus that every option carries the same header (with its "Option X" label), navigation, windows, Track Map and dock, the absence of dropdowns in the header, navigation, visualizer and dock, the empty visualizer above the dock, and the absence of audio and video elements.

**Option B “Midnight Signal” design study.** B has its own visual composition based on the supplied midnight dashboard reference: a continuous 78px header, slim navigation rail, unequal workspace columns, 24px spacing, matte ink-blue cards and restrained cyan signal marks. The header and player are separate components in `LayoutLabMidnightChrome.tsx`, with local state only. The header uses named output segments, readable metric pairs, circular utility keys and a new geometric brand mark. The player is a single 126px shelf with a record sleeve, track metadata, transport and volume, waveform progression and time, a large tempo figure with a BPM override slider, a six-key utility grid, Replace Track, zoom and new Source/Playlist popovers. The waveform seeks and zooms; playback advances its synthetic playhead without playing audio; source, sync, queue selection and playlist preferences are local.

B's visualizer remains empty. The reference guides the styling of existing UI only; it adds no charts, metric displays or scene content. The existing Track Timeline, Cue list, Track Map, Settings and Pop-ups groups remain accessible by scrolling the center column.

`layoutLabOptionBStyle.css` changes component geometry as well as colour: sentence-case segmented main tabs, 38px boxed fields and dropdowns, sliders with visible ring handles and separate numeric wells, sliding boolean switches, recessed collapsible group cards with circular chevrons, larger media/preset cards with separate captions, roomier tracks and notices, rounded timeline cues, taller cue-table rows, swatch tiles and a matching colour editor, larger settings fields, and spacious dialogs and menus. Every existing left/right tab and center group participates. Authored artwork, palette values and semantic timeline colours remain content. The smaller layout uses narrower gaps and a 260px media rail to keep the controls readable.

B opts into `data-ui-theme="midnight"` and `data-ui-typography="midnight"`. Helvetica Neue / Helvetica / Arial typography is defined centrally in `src/styles/typography.css`: 12px regular fields and values, 12px medium tabs, and the existing 12px/700/0.15em parent-heading and 11px nested-heading hierarchy. `AppIconAppearanceContext` switches B to original 24-unit monoline artwork in `outlineGlyphs.ts`, including its nav, controls and portaled content; other options and production keep their existing artwork. Dropdowns, information popovers, palette editors and slider value bubbles carry the theme and typography across portals. Popovers and value bubbles use the anchor's document so they appear inside Layout Lab's separate window.

Select **B** in Layout Lab to review. All existing fixture content remains available, including the Brand Kit placeholder. Closing Layout Lab discards local changes. Production audio, output, projects and the other design options are unchanged.

**Options H, I and K use radial engine selectors.** `radialEngine/LayoutLabRadialEngine.tsx` replaces the left window's engine card (through the optional `engineSlot` prop of `LayoutLabElectricStormLeftWindow`, whose default is unchanged) with a button that keeps the production card's markup and opens one of three pop-outs, portaled into the card's own document so they work inside the separate Layout Lab window. The six choices are production's engine list (`REACT_ENGINE_IDS`). **H · Dial fan:** a rotary dial that hangs from the dotted mark at the right end of the engine card, joined to it by a tether and growing out of it: a ring of engine sectors around a knurled hub; the focused sector lifts, a leader line runs to its label, and the labels fan out to the right in a stack that recedes with distance. **I · Orbit:** round keys spring from the card's icon along a dashed half-orbit, each trailing a label pill, with the focused engine's description beneath the arc. **K · Rotary:** a wheel hanging from the same mark, its fixed pointer directly under it and joined to it, that turns under that pointer; the centre key confirms.
