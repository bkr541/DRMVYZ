# Layout Lab blank canvas

Layout Lab opens a blank canvas shaped like the React View: a **blank header group** across the top, a **blank navigation column** on the far left, an **empty left window**, an **empty middle visualizer**, an **empty right window**, and the **bottom audio dock**.

There are no dropdowns or other selectors anywhere: no design picker, no engine picker and no inspector tabs; the header group and navigation column are empty surfaces. The windows and visualizer contain no content, and the rails have no collapse handles.

**Dimensions match React.** The canvas is built from the same markup and classes as the app (`FloatingWorkspaceFrame` → `.fw-app-shell` → `.vz-main` → `.rv-shell--floating` → `.rv-layout`, rails with `rw-frame--left/right`, the dock as the shell's second grid row), so every size comes from production's own CSS: the 9px outer inset, 11px gaps, 22vw clamped rail width and 106px dock. A blank header group sits across the top (the production header surface, 60px, with nothing in it) and a blank navigation column on the far left (the production compact navigation surface, 72px wide, empty), so the stage region is the same size and position as in the app. Measured against the real `ApplicationWorkspaceFrame` (real header and sidebar) at 1600×1000, 1280×800 and 1000×700, the left window, visualizer, right window and dock rectangles are identical (1600×1000: windows 352×794, visualizer 773×794). The visualizer is the stage above the dock. In design A it shares its column with the Track Map workspace, as in React, so its height matches the app's (773×529 at 1600×1000); designs B–E have no workspace under theirs, so their visualizers are taller.

**Five designs, A–E.** Five buttons labelled A, B, C, D and E are pinned to the bottom of the navigation column. Each selects one of five independent designs (the old Layout Lab's design options): only the selected design is shown, the others stay mounted and hidden so each keeps its own state, and the selected button is highlighted. Every design is a full copy of the page (header group, navigation column, windows, visualizer, dock) with its own switcher, so any view can change the selection. All five start with identical geometry; each is themed through `.ll-design-workbench[data-lab-design='design-0N']` rules in `layoutLabDesignWorkbench.css` (A is `design-01`, E is `design-05`), and the catalog lives in `layoutLabDesignCatalog.ts`.

**Design A mocks the React header, the navigation bar and the Cinema 2.0 windows.** Its navigation column holds the production left-nav options (`LayoutLabReactNav.tsx`): React (active), the Managers label, Preset, Show, Lyric and Media Manager, and the licence and version footer, in the compact sidebar's markup and classes. Clicking an option only moves the highlight; nothing routes, and there is no audio-engine check on Show Manager. The A–E switcher sits between the options and the footer. Its header group holds the elements React View puts in the application header (`LayoutLabReactHeader.tsx`): the DRMVYZ brand toggle, the centred output controls (OUTPUT PREVIEW, Reveal, Blackout, shown idle as in production's non-LaserDMX state), the Layout Lab button, the status cluster (Loading / Saved, FPS / Frame Time, Quality / CPU, Notifications) and the profile button. It reuses the presentational production pieces (the brand toggle, header control group, metric chip, metrics builder and bell icon) and production's classes, with fixed readings rather than the stores, output controller, CPU probe and account lookup; nothing in it acts on anything. Its left window is React View's left rail with Cinema 2.0 / Electric Storm active (`LayoutLabElectricStormLeftWindow.tsx`): the React Workspace header, the engine card, SOURCE / LAYERS tabs, and the Media Library group with its filter tabs, search, grid/list toggle and a 24-tile media grid. Its right window is the Inspector's DESIGN tab with the MARQUEE preset loaded (`LayoutLabMarqueeRightWindow.tsx`): PRESETS / DESIGN / REACT / OUTPUT, ENGINE / SELECTION, and the four parent groups (Master Controls; Design with Pattern, Marquee Copy and Lighting Zones; Effects; Palette) with the preset's real labels, ranges and defaults, starting on the values in the production screenshot. Both are built from the production components and classes (`RailWindowHeader`, `RailTabs`, `Collapsible`, `UnderlineTabs`, `PanelSubtabs`, the control rows, the media sheet card classes) with local state only, so they match production's look and respond to input but touch no store, runtime or media service. They are the only dropdowns on the canvas (Pattern and Trigger, and the engine card, which opens nothing). Its inspector's other tabs are mocked too. **PRESETS** is the Cinema 2.0 preset browser (`LayoutLabCinema2PresetsTab.tsx`): SYSTEM / USER, the search row and the two-column poster grid of the presets Cinema 2.0 really ships, read from the engine registry with the same filter as production; the production panel's account-catalog lookup is left out because it calls the backend, and loading a preset only moves the highlight. **REACT** is the Canvas engine's routing surface (`LayoutLabCanvasReactTab.tsx`): ROUTING / ANALYSIS with Effects first, then Performance Automation, Motion and Preset FX (production's order), shown for the Glitch Pulse preset (a standard preset that declares both FX and Motion) with production's labels, ranges, colours, defaults and option lists; Auto Performance and Pool Automation switch each other off and gate their dependants as the production handlers do. ANALYSIS is empty because it renders live diagnostics. The fourth tab, **AUDIO** (in place of OUTPUT), is the Audio Intelligence window from the Track Timeline Visualizer (`LayoutLabAudioIntelligenceTab.tsx`): the real `MusicIntelligenceDiagnosticsPanel` with its Track header grid, window header and every section (Audio Bands, Rhythm, Beat Grid, Musical Phrases, Energy, Measurements, Section, Section & Structure, Event Markers, Harmonic, Stems, Lyrics, Semantic). It reads a fixed frame and analysis from `layoutLabAudioIntelligenceFixture.ts` instead of the live audio bus, through the panel's optional `frameSource` prop (which defaults to the bus, so production is unchanged). Values differ field to field on purpose: bars run from near-empty to full, some dots are lit and some not, and every section has text, so each state can be reviewed with no audio playing.

Designs B–E keep an empty header group, an empty navigation column (only the switcher) and empty windows. The media tiles are gradient placeholders, not the library's artwork.

**Design A's Track Map workspace mirrors React's.** `LayoutLabReactTrackMap.tsx` is the performance timeline workspace under the visualizer: the toolbar (Track Map / Performance Pads, the row-icons key, Cast, Stage Focus, the collapse chevron), production's resize handle, and the Track Map surface with its lanes in production's order: Beats, Sections, the marker rows (Cues, Phrases, Moments, Actions) and the Time ruler, with the shared playhead. It uses production's own pieces where they stand alone (the real `SectionTimeline`, the beat-grid and ruler canvas drawing, the lane icons, the cue row layout and staggering, the section detail overview) and its markup and classes elsewhere, fed placeholder data from `layoutLabTrackMapFixture.ts` so every row and mark kind shows: an imported Rekordbox beat grid at 129 BPM; twelve sections covering every section type, from Rekordbox, automatic, user-edited, user-created and fallback origins, four with preset badges; Rekordbox hot cues A–H, memory cues and loops beside two manual cues (with bar, beat and snap detail in their titles); structural phrases; semantic moments; and preset and PixGrid actions, one disabled. Click a section for its detail overview (bars, intensity, preset, confidence tier, family and occurrence), a marker to move the playhead, and drag the handle to see the lower rows. Boundary dragging, the section editor and context menus are not part of the mockup. Performance Pads is an empty tab. The embedded Track Map shows no Rekordbox title / artist / BPM / key header; those appear in the Track Timeline's Audio Intelligence window, which is the AUDIO tab.

**Design A's dock mirrors React's.** `LayoutLabReactAudioDock.tsx` is written from the production dock (`VyzualzAudioDock` as React mounts it: `expandable`, `showAudioSourceControl`, Track Timeline key in the lower slot): the same three regions and cards, previous / play / next, volume, Replace Track, waveform and zoom keys, the BPM block with its scrub bar, the Source line, TAP / CUE / SYNC, the Playlist and Track Timeline keys, the Audio Source popover (Input and Rekordbox menus) and the Playlist popover, and click-empty-space-to-collapse. Its state is local (a three-track queue, a fixed 129 BPM), so nothing plays or loads. The waveform is production's own deck canvas (`RgbWaveformCanvas`, as `PeaksWaveformView` renders it in React) drawing a generated loaded-track analysis (`layoutLabWaveformFixture.ts`: a quiet intro, build, drop, breakdown, second build and drop, and outro) with five cue flags and the playhead; the zoom keys zoom it, clicking it moves the playhead, and the playhead advances while Play is on. No audio is decoded or heard. Checked against the real dock in a browser at 1600×1000 and 1280×800, every region, card, key and block lands on the same rectangle; the only difference is the width of the BPM figure, which follows its text (that comparison was made before the waveform canvas was added; the canvas sits in the same waveform slot). Designs B–E keep the older dock mockup described next.

The dock is the existing disconnected dock mockup (`TemplateAudioDockMockup`), which uses the production dock classes and has local-only state. It contains no dropdowns. Its text labels on TAP / CUE / SYNC are hidden (production's keys are icon-only and the labels overflowed the dock grid).

The canvas mounts no production rendering, audio, or media runtimes and makes no changes to saved projects. Closing Layout Lab discards its local state.

Structure lives in `LayoutLabDesignWorkbench.tsx`; popup stylesheet mirroring (`LayoutLabModal.tsx`) is unchanged. The earlier component studies and workspace previews (`LayoutLabReferenceMockup`) remain in the source as references and are no longer mounted by Layout Lab.

`__tests__/LayoutLabDesignWorkbench.test.tsx` covers the A–E switching and independent state, plus the absence of any dropdown, tabs or selector roles, the three empty regions above the dock, and the absence of canvas, audio and video elements.
