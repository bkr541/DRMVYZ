# Cinema 2.0 cinematic model effects (Phase 03)

## Integration and use

All six existing 3D model preview IDs and revision 1 remain intact. The shared factory adds the following inspector groups under **Effects** and **Palette** (the existing four Design parents, model selector, camera, choreography and audio intelligence remain unchanged). No dependencies or lockfile changes are needed.

* **Cinematic Materials:** Original retains the existing source material and textures. Chrome, Black Chrome, Gold, Iridescent, Glass, Neon and Holographic apply reversible surface profiles to representation-owned materials; material controls multiply profile values. Existing texture maps and shader hooks are preserved. The Fresnel shader is evaluated on mesh normals in view space, rather than as an image-space outline. Dust grains and wide hologram lines retain their original shaders and receive the profile's color/emission treatment. Physical transmission, iridescence and clearcoat are available on imported physical materials; standard materials use alpha transparency for glass and the normal-dependent shader for iridescence. Transparent surfaces can still have sorting limitations, especially during crossfades. Fresnel rim energy is an emissive highlight contribution, not a separately masked bloom render.
* **Studio Lighting:** shared ambient, key, fill and stage rim lights are bound to the native lighting runtime. Directional lights aim at the model node; change their positions to change lighting direction. An additional bounded point light sits outside the model pivot and has static, orbit or sway motion, speed, color, intensity and range controls. The shipped studio HDR environment supplies reflected light; its contribution is adjustable on material profiles. The existing bridge's shadow policy supports authored spot shadows, but this phase does not expose a dynamic shadow toggle. Point light animation is visual time, not a separate musical clock.
* **Atmosphere:** existing depth fog and the depth-aware volumetric atmosphere effect provide adjustable color, density, distance and drift. Atmosphere is opt-in and uses the existing quality-scaled ray-march implementation; it is a real-time approximation, not a physically accurate participating-media simulation. The optional screen-space reflective floor is a virtual plane at world Y=0, with ordinary screen-space limitations (off-screen geometry is unavailable).
* **Helix Geometry:** optional procedural tube follows a 3D spiral; radius, turns, tessellation and thickness are geometry-build controls, with bounded tessellation per quality tier. Rotation and emission are inexpensive runtime values. The helix is an optional companion source and does not replace the selected imported model.
* **HDR Glow:** scene, floor, atmosphere, bloom and optical intermediates are RGBA16F with declared RGBA8 fallback. The existing Three bridge writes the display-encoded convention and leaves tone mapping off; native HDR bloom decodes to approximate linear light, applies a soft threshold and quality-scaled mip chain, then re-encodes. Filmic finishing applies exposure and highlight rolloff before writing RGBA8 for temporal history. The inherited gamma-2.2 approximation is not a new exact sRGB/scene-linear pipeline; fallback devices cannot retain HDR highlights. Bloom radius is the existing spread control, not an independent pixel-radius kernel.
* **Optical FX:** enable the stack to combine aspect-correct radial twist, smooth multiscale liquid distortion, sector symmetry, channel separation and animated rotation. Zero intensity disables each individual operation. Distortions are image-space operations, not mesh topology deformations. The center is shared by the optical effects. Low quality caps the procedural flow octaves at two; all optical operations share one fullscreen pass rather than separate full-resolution passes.
* **Temporal Trails:** opt-in extension of the native history service, after tone mapping to match its RGBA8 allocation. Trail length is per-60-Hz retention; decay is its exponent, tint colors the history, and motion sensitivity gates by frame-to-history color difference (not optical flow). Highlight-gated, max-based history does not add unbounded energy. Disabling the effect retires its instance and history, while existing engine seek/resize/source/context resets remain in charge. Legacy presets retain their original feedback shader behavior.

**Load Cinematic Look** applies an atomic canonical parameter patch (Dark Studio, Black Chrome Neon, Gold Reflection, Glass Energy, Electric Hologram, Cinematic Atmosphere, Neon Kaleidoscope). Subsequent controls remain independently editable; Manual does not discard user edits. The look selection and resulting parameters serialize normally. Runtime floats have stable parameter IDs and modulation/choreography flags, with geometry rebuild controls intentionally excluded. No independent beat detection or transport is introduced. The graph always evaluates in the order: model geometry and material shading → floor → atmosphere → HDR bloom → optical distortion → filmic finish → feedback → output. Disabled effects are bypassed by the shared effect runtime. No cast sizing, DPR or output policy is changed.

## Ownership and validation

Material hooks wrap and restore existing representation hooks; temporary material edits do not touch the lease-owned source. The stage owns its helix geometry/material and point light. Geometry changes dispose the previous tube; detach releases the stage and representation-owned resources. Existing render graph, target pool, history service, quality tiers and context lifecycle remain responsible for GPU target resources. No new external library is used.

Run after `npm ci`:

```sh
npx vitest run --config vitest.node.config.ts src/components/vyzualz/cinema2/model/Cinema2ModelCinematicEffects.test.ts src/components/vyzualz/cinema2/model/Cinema2UnifiedUserModelEffects.test.ts src/components/vyzualz/cinema2/__tests__/Cinema2HdrBloomEffect.test.ts
npm run typecheck
npm run verify:fast
```

The implementation environment could not resolve npm registry DNS and its cache lacked project dependencies. `npm run typecheck` stopped at missing `vite/client`; `verify:fast` passed hygiene, legacy boundary, asset checks and stopped at missing installed Three decoder files. The native compiler and state serialization were exercised via a dependency-isolated TypeScript loader (only the Three module type ID import was substituted with its exact authored constant). This does not replace runtime tests. Chromium failed graphics initialization, so actual GLSL compilation, WebGL captures of imported models, context recovery, cast stability, visual comparisons, GPU memory and frame-rate validation are not established. Validate on the installed application with actual vehicle and statue assets, each mode and look, and all combinations of optical effects, quality tiers, resolution changes and casting before release.
