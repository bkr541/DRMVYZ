# React Output inspector

All selectable React engines share `ReactOutputWorkspacePanel` and the approved Layout Lab 05 `OutputHeaderTools`. The study still simulates capture; the inspector connects to the view-level recorder. LaserDMX retains its Production surface and Cinema 2.0 retains collapsible Runtime Diagnostics. Deferred Fractures and unresolved renderers show the same layout with capture disabled.

- Framing: the six Cast Output ratios use `performanceOutputSize`. The stage uses the selected recording aspect unless a cast owns the stage. Capture uses a fixed-size canvas and preserves composition with black padding if the cast ratio differs. PNG screenshots use the same dimensions and framing. Screenshots of frame-publishing WebGL renderers wait for a completed frame.
- Video Settings: 24/30/60 fps and 4/8/12/16/24/40 Mbps are encoder targets. The actual frame rate and bitrate depend on rendering and encoder capacity. The recording follows the currently published program canvas, including stage transitions, without recording editor chrome. Active program audio is included when available at recording start. Source transitions hold the last valid picture while a new renderer resolves.
- Formats: WebM, MP4 and MOV are offered only when the running MediaRecorder advertises the matching container. Chromium typically does not expose a native QuickTime encoder, so MOV is disabled rather than relabeling MP4. There is no new encoder dependency. The saved extension matches the actual container.
- Settings live in the recorder at workspace level, not in presets or tabs. While recording, settings are locked and Stop & Save stays available. Screenshot remains available when the output canvas is available. Recording failures and screenshot errors are surfaced; capture never searches for unrelated canvases.
