# QA-06 camera and pattern perceptibility

## Scope and source audit

The QA-02 reviewed inventory is the 21 compiled IDs in `reviewed-release-inventory.mjs`; no catalog entries, parameters, defaults or Inspector groups were changed. Each run records compiled manifest cameras (rigs, variants, controls, safety, tempo bindings), parameters, module bindings, Pattern options, canonical triggers and source capabilities. The actual shared trigger list is `beat`, `kick`, `snare`, `downbeat`, `beat2`, `beat4`, `bar`, `bar4`, `bar8`, `phrase`, `drop`; the runner checks the full set, not only the count. Livewire is a static rig with authored additive sway, not a flight rig; its existing `flightSpeed: false` remains intact. Its LED patterns change illumination topology and timing, not glyph geometry. Purity is a static perspective with native forward geometry travel. Colossus and Honey have authored physical pose programs. Other static cameras with no authored motion or permission are explicitly classified by the compiled rig; no universal flight requirement is introduced.

Confirmed source defect: the shared pattern latch stored only the latest identity per trigger. A/B/A was accepted as three events, even after a manual selection. The replacement retains the last 64 distinct identities per trigger in the same transport epoch, suppresses replays in that window, and clears only on the existing reset path. This is bounded memory, not an unlimited historical guarantee. Source changes and seeks still establish fresh event history. No new audio analysis, scheduler or persisted state. The shared Mainframe and typography controllers retain their existing manual selection and trigger policies. Livewire inspection reports inherited typography IDs; the release runner normalizes those IDs against the authored Livewire dropdown without changing existing production diagnostics or the dedicated Livewire browser contract. Artifact-family cycle expectations use the authored ordered list; Livewire uses the same deterministic permutation as its typography controller.

## Evidence added to the existing release matrix

- Every supported trigger is routed through the real audio bridge, conductor and module. The fixture publishes one explicit upstream event at a time, including nonqualifying subdivisions, duplicate identity, quiet hold, pause/resume and disabled Pattern Change. A forward seek establishes the disabled-event checkpoint and the next trigger begins with a backward seek. No assignment to effective pattern state. Compare the authored next pattern, observed effective trigger/change, canonical event identity and saved values. The original drop manual takeover/stale/fresh sequence remains. Unit tests exercise all eleven canonical routes, no-source/pause rejection, replay A/B/A and the bounded history reset.
- Each manual pattern is sampled twice from the same seed, activation state and saved values, at three matched breakdown checkpoints, with camera held. Compare every unordered pair at each checkpoint in both repeatability directions; at least one matched checkpoint must exceed both noise baselines. Retain build/drop captures and motion diagnostics. The threshold is the existing QA-01 edge ROI floor (mean > 0.25, changed fraction > 0.002, both > 2x repeatability). It measures visible spatial/lighting difference, not proof of physical displacement; Livewire evidence is LED topology/timing. No preset-specific artistic threshold has been calibrated without actual frames. Purity additionally checks native forward travel strictly increases over the three moving checkpoints, without asserting perceived direction.
- Camera sequences restart from matching saved values and collect idle, two build, two drop, breakdown and paired paused frames. Capture hard off twice, on, supported safety modes, supported amount extrema, kick zoom, BPM Sync off, Auto Performance and portrait. Hard off and lockoff require stable position, target, FOV, roll and clipping planes; pause checks the settled pose. Projection diagnostics use fixed world probes (independent of animated scene geometry), require at least 1 px of in-view displacement when enabled, and reject reduced motion exceeding the full reference by > 1 px. Validate lens/target clip and authored lens bounds. The matched OFF/OFF/ON rendered comparison also requires equal inspected motion diagnostics, unchanged noncamera settings, matched fixture time and edge ROI differences above noise. Camera-only projection probes and edge differences do not establish full imported-source clearance or perceptual quality; absent evidence remains incomplete rather than a pass.
- Existing QA-04/05 source and portrait scenarios, QA-01 technical gates, QA-02 inventory and dedicated Honey/Purity regressions remain intact. No parallel release script. Existing frame and saved-settings gates still apply; schema configuration identifies the changed QA-06 fixture so older performance baselines are not silently treated as comparable.
